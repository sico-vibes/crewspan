Prefer vertical slices that reuse Drizzle schema/export and migration paths, shared validators/types, Express routes/services, and React pages. Authorization has a grant table/evaluator and access routes to extend; task completion already links results, assessments, approvals, work products and costs; the adapter runtime exposes a Bubblewrap/sandbox seam. Further inherited seams include adapter plugins and plugin routes (doc/PRODUCT.md, doc/SPEC-implementation.md, server/src/routes/plugins.ts), routines (server/src/routes/routines.ts, server/src/services/routines.ts), workspace/runtime services (server/src/services/workspace-runtime.ts, server/src/services/execution-workspaces.ts, packages/db/src/schema/workspace_runtime_services.ts), and provider-backed asset storage (server/src/services/assets.ts). These are extension points, not proof that Crewspan's target contracts are satisfied. Preserve single-assignee tasks, atomic checkout, approval gates, budget hard stops, activity logging, company scoping, and PRP/API compatibility. The fork boundary inventory documents operational and protocol identifiers with high sync cost; avoid broad renames while Board identity decisions remain open.

- **Runtime overclaim:** clean Git state does not prove service configuration or isolation. Telemetry, auth mode, sandbox activation, provider credentials, MFA, backup status and live security probes were not inspected.
- **Permission retrofit size:** company scoping and action grants do not equal filtered resource authorization. Inventory route, query, search, event, count and agent-tool coverage before estimating M2.

FORK-BOUNDARY.md §6 lists telemetry, announcements, update channel, branding depth, and Paperclip Cloud choices. Do not infer the live VPS choice from source defaults.
